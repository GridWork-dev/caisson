### apps/site/app/security/page.tsx:67

**Security/trust page falsely claims the site is a static export with 'no application server, no database, no runtime data fetch'.**

- **Evidence:** SITE_POSTURE[0]: { icon: "server", title: "Static export, no runtime", body: "The site is a static export — no application server, no database, no runtime data fetch. The contact-forms endpoint is the only dynamic surface..." }. This is false: my own slice contains app/api/auth/[...all]/route.ts (export const runtime = "nodejs"; export const dynamic = "force-dynamic"; better-auth handler needing DATABASE_URL), app/dashboard/layout.tsx (export const dynamic = "force-dynamic"; requireDashboardSession authed dashboard), and lib/dashboard-reads.ts (reads Postgres usage_event/credit_wallet/entitlement_grant/license_grant via readScoped→withTenant RLS). Plus /api/search, /api/byok, Paddle checkout, sign-out. The site is a dynamic Next standalone app on Railway per ADR-0114/0115 (deployed 2026-07-01).
- **Why it matters:** Violates the ADR-0080 precise-scope honesty law + ADR-0082 'artifacts true-to-built'. Impact: on the /security page procurement reads first, it materially misrepresents the attack surface — claiming no application server and no database when both exist and hold buyer accounts, credit ledgers, and entitlements. The page's own CSP block (allowing cdn.paddle.com for dynamic checkout) proves it was only partially updated, confirming stale copy, not intent. Deterministic gates (token-drift, standards-gate, oscal) do not verify marketing copy against deployment architecture, so this passes green.
- **Verdicts:** refuted=false · refuted=false → CONFIRMED

### apps/site/app/legal/license/page.tsx:84

**The legal license-summary page falsely claims the entire @caisson library is commercial with no permissive tier, contradicting the Apache-2.0 open-core base.**

- **Evidence:** Line 77+84: "Caisson is a fully commercial developer library. Every module ... ships under a single proprietary Commercial License (LicenseRef-Caisson-Commercial). There is no AGPL, free, or permissive tier." Line 195-196: "One license, the whole library. Every package under the @caisson scope — the base, every module, and all four editions — ships under the same commercial license." The per-module card (lines 222-233) lists @caisson/base, @caisson/auth, @caisson/tenancy-rls, @caisson/billing, @caisson/ai-config under a "Commercial" chip footnoted "no redistribution of the kit." But `packages/*/package.json` show kernel, auth, tenancy-rls, billing, ai-config, ui, credits, mcp-server, cli, migrate, license-verify all carry "license": "Apache-2.0" — a permissive tier that explicitly permits redistribution.
- **Why it matters:** Violates the honesty laws (ADR-0080) and directly contradicts the ADR-0094/0097/0136 open-core relicensing that the standards-gate itself enforces on package.json. Impact path: this is the canonical, buyer-facing license summary — it misrepresents the legal rights recipients actually have, telling users they may not redistribute code that is in fact Apache-2.0 (redistribution is expressly granted), and denies the existence of a permissive tier that ships in the repo today. A gate checks the SPDX field in package.json, never the marketing prose, so the contradiction is invisible to CI.
- **Verdicts:** refuted=false · refuted=false → CONFIRMED

No deterministic gate compares MDX prose to pricing.ts, so it ships green. Impact: a prospective buyer reading the Local-first edition docs is quoted a higher, "from"-framed price that the /pricing page ($349 fixed) directly contradicts.

## Coverage gaps (completeness critic) — the next audit round

The 0-finding domains (security 589 files, rls-tenancy, licensing-spdx, evidence-compliance) are **not proven clean** — the critic judges the domain globs did not reach the risky surfaces. Gaps:

- Python surface (services/support-bot, 22 .py files) is entirely outside a TS-glob security scan. Un-scanned finding classes: indirect prompt injection where rag.py feeds untrusted retrieved docs into the OpenRouter prompt; Discord authorization on privileged commands in member_mgmt.py + bot.py (self-assignable roles = a privilege-escalation surface, ADR-0109); pydantic secret/token handling in config.py; the gridwork timing-safe-compare / authz rules are never applied to the Python idiom.
- CI/CD workflow security (.github/workflows/_.yml, 6 files) is covered by no domain. `on: pull_request` jobs run on the self-hosted fleet [self-hosted, gw-linux-amd64] in ci.yml/quality.yml/support-bot.yml — the safety rests on a throwaway-docker posture claim this audit never verified. Un-checked: per-workflow `permissions:` least-privilege, deploy-railway.yml prod RAILWAY_TOKEN handling, publish.yml npm-publish token, and GitHub-Actions script-injection (current github.event._ interpolations sit in concurrency.group not a run: shell, so low-risk — but nobody confirmed it).
- Container + IaC surface (6 Dockerfiles, infra/signoz/docker-compose.yaml + otel-collector-config.yaml, 5 terraform .tf) is unscanned. infra/terraform/access.tf is the Cloudflare Access authorization policy gating admin.caisson.sh + license + docs — a live authz control no domain audited (who-can-reach-what). Dockerfile base-image pinning / non-root USER / build-arg secret leak also uncovered. (tfstate/tfvars are gitignored — not a git-leak.)
- Telemetry/observability egress (ADR-0117, external Grafana/SigNoz sink) is not a listed audit domain despite being an external data-egress boundary. The new request-span.ts uses the raw URL pathname as the span NAME and http.route attribute with NO scrubbing — a license key, token, or email embedded in a path segment egresses unredacted. scrub.ts exists but is a loose key-regex deny-list (allow-list would be safer); a mis-keyed sensitive attribute slips through. Sensitive-data-in-telemetry is a cross-cutting class no single-domain finder owns.
- Financial-correctness / integer-money invariant (ADR-0007) has no owning domain. pricebook (actions.ts), billing (Stripe->credit-grant idempotency/replay), and credits denomination are un-audited for float-money, rounding, and double-grant. Specifically the new BYOK keySource='tenant' -> resolveActionCost 0-credit branch (ADR-0182) is a metering-bypass economic path that got zero adversarial scrutiny.
- Meta-gap: the checkers themselves (tooling/standards-gate, design-critic, eslint-config, testing) were only lightly touched (standards-gate shard = 22 files). licensing-spdx's 0 findings and the clean standards-gate result are only as trustworthy as the gate's coverage — no one verified the gate actually walks every package (a package with no manifest.ts, or a new top-level dir, could be silently skipped) or that the open<->commercial no-depend-up + SPDX checks have no glob blind-spot.
- Registry Worker edge (registry/worker/*.ts) — offline Ed25519 license verification + entitlement filtering + cache headers at the Cloudflare edge — is the license-enforcement boundary and its coverage under the security domain is unclear. Un-verified: entitlement-bypass, cache-poisoning (the prior private/no-store+Vary finding), and the deploy-entry composition seam that silently un-filters if the resolver option is dropped (a documented past gotcha).
- The create-caisson generator (packages/cli) emits scaffolding that ships to customers; insecure defaults or leaked template secrets in generated projects are a downstream security surface no domain models — the audit scanned the generator's own code, not what it produces.
- The 0-finding results across security (589 files), rls-tenancy, licensing-spdx, and evidence-compliance are suspiciously clean given design-ui found 14 and standards-gate found 2 — the finders demonstrably work, so the 0s more likely reflect globs/rule-sets not reaching the risky surfaces (Python, YAML, Dockerfiles, edge Worker, working-tree-new files) than genuine cleanliness.
