## Vehicle fork — item 1 (admin route error mapping)

**Confidence: HIGH — recommend riding `fix/money-path-hardening`.**

- **Option A (Recommended, confidence HIGH):** Add the `mutationErrorResponse` helper + the
  4-route swap as one more commit on `fix/money-path-hardening` before it ships. Evidence: that
  branch is the one that _introduced_ the now-swallowed `NotFoundError` (CAISSON-9, commit
  `76f8859`); fixing the swallow in the same PR means CAISSON-9's fail-closed 404 actually reaches
  the operator the first time it ships, instead of shipping a fixed backend behind a route that
  still reports it as a generic 500 for one more PR cycle. Zero new changeset needed (`apps/admin`
  is an app, exempt from the changeset gate per the repo's own convention).
- **Option B:** Own tiny PR, independent of the hardening branch. Evidence for: keeps the hardening
  PR's diff scoped to money-path logic only, easier isolated review. Evidence against: ships a
  known-swallowed 404 for however long that gap is, on a path that already has the audit
  double-logging expectation from ADR-0220.

Both are cheap (S-sized, no schema/migration involved); this is a sequencing call, not a design
fork — proceeding with Option A unless redirected.
