# W1 Research 1/4 — ADR-0244 window-check enforcement point

## 1. Current data flow (purchase → issuer → claims → resolver → Worker → client)

```
Paddle purchase.completed webhook
  → services/license/src/app.ts:290-334 (POST /webhook)
  → handleBillingWebhook → apply-billing-event.ts (one_time grant, ADR-0113)
  → entitlement_grant row: (account_id, entitlement_id, source_kind='one_time',
    purchase_id, granted_at=now())         [services/license/src/entitlement-store.ts:29-51]
                                             ← ONLY existing per-purchase timestamp today

Buyer calls POST /issue (app.ts:198-288)
  → resolveAccountEntitlements(tx, accountId, index)   [resolve-entitlements.ts:25-32]
      reads readEntitlements (purchased ids) + expandEntitlements(index, purchased)
      → flat member-module slug Set<string>, NO per-version/date info
  → claims = { licenseId, tier, entitlements: string[], major, expiry }  [app.ts:244-250]
  → issueLicense(signer, claims)            [packages/license-issue/src/issue.ts:30-49]
      strict-parses claims via licenseClaimsSchema (packages/license-verify/src/claims.ts:37-43)
      — schema has NO purchase-date / window field at all, only
        {licenseId, tier, entitlements[], major, expiry|null}
      signs canonicalize(claims), returns wire token
  → storeLicenseGrant (idempotent per (accountId,major))

Buyer's install/registry client sends `Authorization: Bearer <token>`
  → registry Worker: entitlement-filter.ts:28-45 makeLicenseEntitlementResolver
      verifyLicense(token) [license-verify/src/verify.ts:74-142]
        — checks signature, canonical bytes, expiry (whole-license, not per-version)
        — returns claims.entitlements (module-id list) or COMMUNITY
      checks getDenied().has(claims.licenseId)  (ADR-0225 R-4 deny-set)
  → handler.ts:58-72 entitledModuleSet = baseModuleIds(index) ∪ expandEntitlements(purchased)
  → serves index.json / /modules/:id with ALL versions of every entitled module
    (registry/schema/registry-index.ts:21-35 RegistryVersion.publishedAt IS already
    stamped per-version by CI — but nothing reads it for filtering)
  → npm-routes.ts:196-232 abbreviatedPackument — same entitledSet gate, exposes
    every sidecar-packed version of an entitled module id, again no date filter
```

**Key finding: `publishedAt` already exists per-version in the index (`registry-index.ts:26`, populated in `registry/index.json`) but is used only as provenance display — it is not read by any gating code path.** The window check is 100% unbuilt: no claim field carries a purchase date or window bound, and no server/edge code compares a version's `publishedAt` against anything.

## 2. Per enforcement point

### Issuer-side claim (embed the window in the signed token)

|                                   |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Has today**                     | `granted_at` per `entitlement_grant` row (earliest = purchase date), `expiry` field already on claims (currently used for subscription-style hard expiry, not a rolling window)                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Must add**                      | A new claim field, e.g. `updatesUntil: string \| null` (ISO instant) on `licenseClaimsSchema` (claims.ts:37-43) — a **breaking schema change**, since it's `.strict()`. Issuer (`app.ts` `IssueBody` + claims construction, app.ts:88-95/244-250) must compute it: `min(purchase.granted_at) + 12mo`, extended per renewal purchase. Needs a way to look up the earliest `granted_at` across the account's active one-time grants for that entitlement set (a new query beside `readEntitlements`).                                                                                     |
| **Offline semantics**             | Fully consistent with ADR-0010's zero-phone-home model — the check becomes `version.publishedAt <= claims.updatesUntil`, evaluated **client-side or edge-side against the already-signed claim**, no extra round-trip.                                                                                                                                                                                                                                                                                                                                                                  |
| **Revocation/deny-set interplay** | Orthogonal — `licenseId` deny-set (ADR-0225 R-4) still fully applies on top; a window-expired-but-not-revoked license just serves fewer versions, doesn't need denying.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Grandfathering hook**           | Clean: `updatesUntil` is computed once at issue time from real `granted_at`; a pricebook/window-policy change post-issue never reaches already-issued tokens (append-only, matches ADR-0106's "no retroactive obligation" framing) — but this is a **double-edged clean**: it also means an operator who wants to _extend_ a window for existing buyers (grandfathering forward) must re-issue, not just flip a server-side flag.                                                                                                                                                       |
| **Already-issued licenses**       | **Every token issued before this ships has NO `updatesUntil` field.** Verifier must treat absent field as unbounded (`updatesUntil: undefined → no window limit`) to avoid retroactively cutting off pre-launch/early buyers — but that is exactly the unbounded-free-updates failure mode ADR-0244 exists to close. Requires either a re-issue sweep (the idempotent `/issue` persist-and-reuse model at app.ts:220-230 actively works against this — it will keep re-serving the OLD stored token forever unless invalidated) or a schema-version bump the verifier discriminates on. |

### Worker-side filter (registry gates by publish date, no claim change)

|                                   |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Has today**                     | `RegistryVersion.publishedAt` per version already in `index.json` (registry-index.ts:26); the Worker already resolves `entitled: Set<moduleId>` per request (handler.ts:58-72, npm-routes.ts:143-158)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Must add**                      | The purchase date is NOT known to the Worker at all today — it never receives a purchase timestamp, only `claims.entitlements` (module ids) + `claims.licenseId`. **This is the blocker**: Worker-only enforcement requires the purchase date to reach the edge some other way — either (a) still put it on the claim (converges with issuer option, just moved the comparison downstream), or (b) a server-side lookup Worker doesn't have (breaks offline model), or (c) derive it from `licenseId` via a side artifact analogous to the revocation deny-set (a signed "license → updatesUntil" map published like `registry/worker/revocation-list.ts`, refreshed on a TTL) — this preserves per-license accuracy without a schema/token change, at the cost of a second edge artifact + staleness window (same STRICT fail-open tension as revocation-list.ts:8-11, but fail-open here means fail-_permissive_, i.e., serving a stale/unbounded view, which is the safe direction). |
| **Offline semantics**             | Breaks pure offline-token verification if done via (c) — now two edge fetches (revocation list + window map) instead of one signed, self-contained token; that's a meaningfully bigger infra lift than the issuer-side claim. If instead the window is embedded in the claim (converging on issuer's field) and the Worker just does the comparison at serve-time against per-version `publishedAt`, this is genuinely cheap — reuses the existing filter architecture 1:1 with `abbreviatedPackument` (npm-routes.ts:196-232) and `/modules/:id` (handler.ts:126-144) each adding one `v.publishedAt <= claims.updatesUntil` predicate per version.                                                                                                                                                                                                                                                                                                                                    |
| **Revocation/deny-set interplay** | Same layering as revocation: apply AFTER the existing entitled-set gate, narrowing versions not modules. Reuses the exact TTL-cache-with-fail-open pattern already proven in revocation-list.ts if going the side-artifact route (c).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Grandfathering hook**           | If window lives in a Worker-side artifact keyed by `licenseId` (not the token), an operator CAN retroactively extend/shrink a specific buyer's window without re-issuing tokens — this is the one real advantage of pure Worker-side over pure issuer-side, at the offline-purity cost above.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Already-issued licenses**       | If the comparison field comes from the claim, same problem as issuer-side. If it comes from a side artifact, already-issued licenses are fine — the artifact is populated post-hoc from `entitlement_grant.granted_at`, no re-issue needed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

### Both (claim carries the window; Worker/npm surface enforces it per-version)

This is really "issuer embeds the data, Worker/npm-surface does the per-version comparison" — not a third independent mechanism, but the natural composition: the issuer is the only place that _knows_ the purchase date (DB-backed), and the Worker is the only place that _knows_ per-version `publishedAt` (index-backed); neither side alone has both facts. **Both must cooperate regardless of which option you pick** — the only real fork is _how the date crosses the offline boundary_ (in the signed claim vs. a separate signed/fetched artifact), not whether one side does the whole job alone.

## 3. ADR-0223 npm surface (self-hosted npm delivery)

The npm packument path (`npm-routes.ts:196-232 abbreviatedPackument`) is where this actually bites hardest: it currently emits **every sidecar-packed version** of an entitled module with no date filter, and `bun install @caisson/compliance` will resolve to `dist-tags.latest` — i.e., **the npm surface as built today silently ignores ADR-0244 entirely and always serves the current latest**, regardless of how old the license's purchase window is. Any window check must filter `abbreviatedPackument`'s `versions` map (npm-routes.ts:207-224) to only include `v` where `v.publishedAt` falls in the license's window, AND must **recompute `dist-tags.latest`** to the newest _in-window_ version (not the catalog's global latest) — otherwise `bun install` still pulls a too-new version via the tag even if the raw version route would 404 it. The tarball route (`TARBALL_RE`, npm-routes.ts:264-287) needs the identical per-version check before the R2 fetch — right now it only checks module-level `gateStatus` (npm-routes.ts:276), not version.

## 4. Trade-off table + recommendation

| Option                                                                                              | Data added                                | Offline purity                                                                                           | Grandfather flexibility                                                                                                                                      | Already-issued licenses                                                                                                                                                                              | Build cost                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Issuer-only claim** (`updatesUntil` on `licenseClaimsSchema`)                                     | New signed field, schema-version bump     | Preserved — one token, zero extra fetches                                                                | Rigid: extending a buyer's window needs re-issue                                                                                                             | Must treat missing field as unbounded (reopens the exact loophole ADR-0244 closes) unless re-issue-swept                                                                                             | Low–medium: touch claims schema, issuer app.ts, verifier, + every consumer of `VerifiedLicense.claims`                                                                                |
| **Worker-only side-artifact** (licenseId → updatesUntil map, TTL-cached like revocation-list.ts)    | New edge artifact, no claim/schema change | Broken — offline token no longer self-contained; adds a second cache/fetch/fail-open surface             | Flexible: operator edits the map anytime, no re-issue                                                                                                        | No problem — backfilled from `granted_at`                                                                                                                                                            | Medium: new artifact format + publish path + Worker wiring, but reuses the proven revocation-list.ts pattern verbatim                                                                 |
| **Both — issuer signs the window, Worker/npm-surface filters per-version against it** (recommended) | Same claim addition as issuer-only        | Preserved for the _window fact_; per-version enforcement is pure index-local computation, no extra fetch | Same rigidity as issuer-only for the window value itself, but combinable with the existing revocation deny-set for a fast "cut off entirely" lever if needed | Same gap as issuer-only — needs an explicit unbounded-if-absent fallback, documented as a known pre-launch grandfather clause (matches ADR-0106 "pre-flip buyers honored" framing), not a silent bug | Medium: claim + issuer changes (once) + `abbreviatedPackument`/`/modules/:id`/tarball-route per-version predicate (three call sites, all already have the `publishedAt` data in hand) |

**Recommendation: Both, with the window in the signed claim (confidence: high).** Evidence: `publishedAt` is _already_ on every `RegistryVersion` (registry-index.ts:26) and already flows into every place that needs to filter (`abbreviatedPackument`, `/modules/:id`, the tarball gate) — so the Worker-side half of "both" is a small, local diff against data that's already there. The purchase-date half can _only_ come from the issuer (it's DB-truth, `entitlement_grant.granted_at`), so a Worker-only side-artifact just re-derives the same fact through a second, staler, fail-open channel for no purity gain once the Worker already has to do per-version math anyway. The genuine open question this surfaces for the operator is the **already-issued-license fallback**: since checkout hasn't flipped yet (ADR-0106 confirms zero live buyers), there is no backfill problem in practice — a schema/claim addition today costs nothing retroactive, so the "unbounded if absent" escape hatch is a moot pre-launch concern rather than a design compromise. Renewal-window extension (`updatesUntil += 12mo`) is a straightforward re-issue at renewal-purchase time through the existing idempotent-per-`(accountId, major)` `/issue` path, once that idempotency key is loosened to also re-mint on a window-extending purchase (currently it would return the stale stored token — **flagged as a real gap for the W1 build**, not solved here).
