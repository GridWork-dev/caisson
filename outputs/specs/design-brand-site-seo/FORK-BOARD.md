## Visual design + craft (43)

### V1 · ★ hero-composition _(high)_

**Q:** How should the home hero be composed, and what carries it?

- Code-in-hero, single left column (current) — honest, on-brand, but leaves the desktop right half empty
- Split: claim + CTAs left / framed terminal artifact (the real RLS denial) right — pairs assertion with proof above the fold
- Editorial headline + abstract object, code demoted below (Resend) — premium but buries the differentiator
- Centered terminal screenshot (Warp) — clean but generic in-category

**Recommendation:** Split hero: claim + CTAs left, a framed terminal showing the real fail-closed RLS denial right. It fills the empty desktop half and puts the assertion beside its proof, which is more differentiated than Resend since the artifact IS the headline.

**Evidence:** refero resend 87fe3d52, pipe c00d3961, SST 7b6c53c7; impeccable empty-right-half finding; page.tsx:60-111

### V2 · ★ hero-install-command _(high)_

**Q:** Should the hero surface the create-caisson install command?

- No install command (current) — keeps focus on the RLS denial
- Add `npx create-caisson` line beside/above the artifact (Ollama/t3 pattern) — instant category signal + a real entry point
- Animated terminal: install -> RLS denial -> audit-chain hash — highest craft, build cost

**Recommendation:** Add the install command alongside the RLS-denial proof: OSS dev tools lead with the command as hero, create-caisson is real but absent from the current hero. Keep the denial as the proof, add the command as the action.

**Evidence:** ollama.com curl hero, create.t3.gg, traceloop 2-line code hero; devtools-aiinfra V1; page.tsx:60

### V3 · ★ marketing-hero-motion _(medium)_

**Q:** Should the hero animate a real fail-closed event as a product demo (the Vercel build-log move)?

- Static crafted artifact + one-shot fade-in + subtle cursor blink — calm, evidence-first, lowest risk
- Animate a real fail-closed event (RLS denying cross-tenant / an audit-chain link appending / a WORM lock engaging) — the thesis demonstrated, not decoration
- Looping typewriter / decorative hero animation — reads gimmicky, off-register

**Recommendation:** A static crafted artifact with a one-shot fade-in for v1, with one animated real fail-closed event as the ambitious option — the product thesis demonstrated serves proof-shown-not-asserted. Never a looping typewriter (breathless, off-brand).

**Evidence:** motion.md Vercel build-log = product demo; SST/Resend artifact-as-hero; refero-screens #32; specs/04 §5

### V14 · sku-section-rendering _(high)_
