## 1. Goal (goal-backward restatement)

Ship the v1 agent-ready surface so a buyer's **coding agent** can adopt `@caisson/ui` with no human reading docs — discover the 38 Apache-base components + their props/variants/tokens as typed JSON, and mechanically verify correct usage — while the paid verify path and any pro metadata stay entitlement-gated behind the existing buyer MCP. Concretely, VERIFY must be able to run the SPEC's three-run acceptance: (1) a **no-credentials** agent reads the committed manifest / calls the local stdio discovery MCP / runs `describe --json` and builds a brand-conformant screen with ≥3 kit components; (2) an **authenticated** agent calls `check_usage` (the static doctor) — zero findings on correct usage, typed findings on deliberately broken usage; (3) an **unentitled** caller against the same authed tool is denied outright. The five slices are independently shippable; nothing introduces a hosted unauthenticated HTTP MCP, and `@caisson/ui` gains zero runtime dependencies.

### Architecture decision (implementation, not an operator fork) — new `@caisson/ds-manifest` leaf package

The five slices need a **shared data + analysis layer** importable by the frozen `packages/ui` generator, `packages/mcp-server`, and `packages/cli` **without a dependency cycle** (mcp-server already needs `@caisson/ui/tokens`, so the schema cannot live in mcp-server; and the ui freeze must not block the four non-ui slices). Recommendation: a new tiny Apache-2.0 `oss` leaf package **`@caisson/ds-manifest`** holding the manifest Zod schema, a typed reader, the extracted `checkContrast` lib, and the pure doctor static-check functions. Dependencies: `zod`, `culori` only (token objects are passed in as arguments, so it does **not** depend on `@caisson/ui` — no cycle). The committed **base** manifest JSON lives here (Apache-open); the **pro** manifest JSON lives in `packages/ui-pro` (commercial, gated). This decouples 4 of 5 slices from the ui freeze: consumers build against a hand-authored fixture manifest until the real generator lands. **Default = create `@caisson/ds-manifest`.** Alternative (no new package): commit the base JSON + schema under a react-free `@caisson/ui/manifest` subpath — rejected as default because it couples every consumer to the frozen ui tree and drags `@caisson/ui` as a dep of cli/mcp-server. This is an executor decision to confirm at EXECUTE, not an operator gate.

## 6. Risks & unknowns

1. **`packages/ui` freeze (Kickoff S) blocks G1.** Mitigation: the `@caisson/ds-manifest` fixture (T0.4) lets G2–G5 build + test to green before the real generator lands; G1 is FREEZE-SEQ and regenerates the committed JSON when the freeze lifts. Risk: Kickoff S renames/adds/removes a component → the manifest count test (T1.3) catches it; regenerate. Coordinate the merge order with the Kickoff S session (both touch `packages/ui`).
2. **`packages/mcp-server` touched by both G4 and G5.** Two parallel writers on one package → reconcile risk (ADR-0328). Mitigation: sequence G4/G5 in one worktree/PR or a dedicated reconcile session.
3. **TS-type → variant extraction fidelity.** Some variant unions are inlined or computed, not exported aliases (P7 shows the pattern is exported aliases, but verify all 38). Mitigation: T1.1 asserts every barrel component resolves a props shape; components with no exported variant union emit `variants: {}` (correct, not a silent drop). ts-morph is a build-time devDep only (no ui runtime dep — honors the non-goal).
4. **`get_tokens` vs deferred DTCG export (P11).** v1 emits the raw `@caisson/ui/tokens` objects as JSON — NOT a third bespoke format. When the DTCG `tokens.json` export lands (reconcile), `get_tokens` swaps its serializer to the DTCG shape. Risk: shape churn for early consumers → document `get_tokens` output as provisional-pending-DTCG. Cross-dep, not a blocker.
5. **Open-core porosity of an Apache doctor lib.** The doctor's static-check logic is Apache source (in `ds-manifest`/`mcp-server`); a self-hoster could run it unpaid. Accepted: identical to the coach precedent — the gate is real for caisson's hosted, license-backed buyer MCP, and the business value is the hosted service + pro coverage + updates (ADR-0094 thesis), not source secrecy. If the operator wants a hard gate, Fork F option (b) is the lever — but that is heavier and out of v1 scope unless locked.
6. **`describe_component`/`check_usage` accepting buyer source over an MCP call.** Input is untrusted buyer file contents. Mitigation: Zod `.strict()` + bounded string lengths on the args (per the repo security floor); the doctor is pure static analysis (no exec, no fs write, no network) — no shell, no path traversal surface. Security audit fires at SHIP (`security` tag).
7. **shadcn install-path namespace (P12) is another kickoff's deliverable.** This surface only _references_ `bunx shadcn@latest add owner/repo/item`; if that namespace slips, the docs pointer (T6.1) references an unindexed path. Mitigation: gate the T6.1 install-path copy on the shadcn task landing; the manifest/CLI/MCP slices don't depend on it.

## 7. Goal-backward verification plan (how VERIFY re-asks the SPEC Goal)

VERIFY does not check task boxes — it re-runs the SPEC's own three-run acceptance (SPEC §Verification) against the merged diff, as executable tests plus one manual agent-session sanity run:

1. **Open discovery (no credentials).** An agent with only the repo checkout reads the committed base manifest (`loadBaseManifest`), and separately a local stdio-discovery-MCP config calls `list_components`/`describe_component`/`get_tokens` — returns the 38 base components with props/variants/tokens, **no caisson token required**. `describe --json` from the cli returns the same data. Evidence: T2.1 golden test + T5.1/T5.2 tests + a manual agent run building a ≥3-component brand-conformant screen.
2. **Authed verify.** An authenticated buyer session calls `check_usage`: **zero findings** on a correct-usage fixture, **typed findings** on deliberately broken usage (wrong token override, invalid `data-variant`, missing `aria-describedby`, version skew). Evidence: T3.2 + T4.1 tests.
3. **Denied when unentitled.** An unentitled/unauthenticated call against `check_usage` / `describe_pro_component` is denied outright — invisible 404 for the gated tool, `EntitlementError` on entitlement inspection, **never a partial pro-shaped response**. Evidence: T4.3 + T4.4.
4. **Boundary invariant.** The stdio discovery server's resolvable set is a strict subset of the base-38 and can never resolve a `@caisson/ui-pro` component. Evidence: T5.2.
5. **Determinism + no-drift.** `bun run gen:manifest` is byte-stable; the drift guard (T1.3) is green. `@caisson/ui` gains **zero runtime deps** (verify package.json `dependencies` unchanged — only a build-time devDep for the generator).

Full-suite gate: `bun run check` (standards-gate + lint + tsc + tests across touched packages), `bun changeset status --since=origin/main` clean, `bun run sot` green. `ai` tag → EVAL act; `security` tag → SECURITY audit at SHIP (focus: the untrusted-buyer-source input surface + the entitlement gate).

## 8. Out-of-scope confirmations (SPEC non-goals restated as guards)
