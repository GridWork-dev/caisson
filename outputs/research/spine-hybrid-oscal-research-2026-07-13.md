## 2. Ground truth that reframes the fork

- **OSCAL is already caisson's output spine.** ADR-0179 (emit OSCAL **v1.2.2** + per-framework AP fragment; FedRAMP 1.0.4 down-convert explicitly deferred), ADR-0180 (JSON+XML export), ADR-0231 (rlink signed bundle, "FedRAMP-recommended integrity pattern"), and CI has an `oscal-conformance` required check. The fork is only about the _internal data model_, not adopting OSCAL.
- **ADR-0057's ban is ND-specific, not OSCAL-hostile.** Binding text: "No CC-BY-ND / NoDerivatives-licensed catalog (SCF first among them) is ever ingested." Rejected-option-3 ("NIST OSCAL public-domain catalogs only") was rejected **on coverage grounds** ("no SOC2/HIPAA crosswalk"), not licensing — it even calls them "freely reshapeable." NOTE: the code comment in `frameworks-pack/src/registry/control.ts:5` over-states this as "or any third-party catalog JSON" — the superseding ADR must clarify that public-domain reference catalogs are loadable as _mapping targets_.
- **The control model is already spine-shaped.** `CanonicalControl.crosswalk: CrosswalkReference[]` with `framework` + `reference` pointer fields (`control.ts:38-46`) — `NIST-800-53` is even the example framework label in the schema docs. Adding an 800-53 axis is data, not schema.
- **The paraphrase pattern for licensed standards already ships.** `frameworks-pack/src/crosswalks/regimes.ts` header: "control ids are bare regime IDENTIFIERS (factual citations), not the requirement text" + own-authored summaries + the honesty floor (implements-only-with-test-proof, ADR-0279). ISO 27001 rides this exact precedent.

## 3. Live-check facts

- **NIST 800-53 rev5 OSCAL catalog is public domain worldwide (CC0 1.0)** — `usnistgov/oscal-content` LICENSE.md waives copyright via CC0; catalog at `nist.gov/SP800-53/rev5/json/NIST_SP-800-53_rev5_catalog.json`. Zero licensing friction to vendor + hash-pin. (github.com/usnistgov/oscal-content/blob/main/LICENSE.md)
- **NIST publishes an official 800-53r5 ↔ ISO/IEC 27001 mapping** (`sp800-53r5-to-iso-27001-mapping.docx`, CSRC supplemental materials; OLIR program hosts the informative-reference process) — NIST work = public domain; maps to ISO control **identifiers** only. Seeds the ISO axis without touching ISO text. (csrc.nist.gov/projects/olir; content.govdelivery.com/accounts/USNIST/bulletins/2bd2e36)
- **ISO 27001 licensing reality:** Annex A control TEXT is ISO-copyrighted and cannot ship; the industry pattern (CISO Assistant, 150+ frameworks incl. ISO 27001:2022 in its AGPL library) is requirement-id trees + own-authored descriptions, with OLIR-standard mappings; frameworks whose licenses forbid even that are marked "bring your own Excel" in their catalog. Caisson's regimes.ts pattern is already exactly this. (github.com/intuitem/ciso-assistant-community; intuitem.gitbook.io framework docs)
- **FedRAMP OSCAL mandate** (machine-readable SSP/CompDef/SAR from Sept 30 2026, per ADR-0179's own citation) means an OSCAL-native spine makes the deferred FedRAMP pack mostly a profile + baseline exercise later.

## 4. Recommended design — "dual-catalog OSCAL spine" (dissolves the hybrid tension)

One data model, two catalogs, mappings as first-class data:

1. **The caisson canonical catalog stays own-authored** (`defineControl`/`defineFramework`, untouched authoring flow) **and gains an OSCAL expression**: generate `caisson-catalog.oscal.json` (caisson URN namespace) from the existing typed data via the ADR-0179 machinery. Product-specific controls (RLS-force, AI-evals, WORM, crypto-shred) live here natively — never force-fit into 800-53. _This is the "not for things that aren't there or optimized" half._
2. **Vendor the NIST 800-53 rev5 OSCAL catalog (CC0) as a reference catalog** — hash-pinned JSON, loaded read-only. It is a mapping TARGET, never the authoring model; the curated ~50-control buyer UX is unchanged. _This is the "full OSCAL as spine" half: the authoritative external axis is the literal NIST artifact, not hand-typed pointers._
3. **Mappings are data rows joining the two** (OLIR-style relationship entries; OSCAL mapping/profile shapes where they fit, CrosswalkReference rows in-repo): caisson-control → 800-53 control(s) where a genuine map exists; absent where not. Rollup ("fix once, satisfy N") computes across these rows + the existing per-framework crosswalks — the join the crosswalk SPEC already scoped.
4. **New-framework recipe (ISO 27001 first):** requirement-id skeleton (bare identifiers = factual citations) + own-authored paraphrase summaries (regimes.ts precedent) + axis seeded from the public-domain NIST 800-53↔ISO mapping doc, then hand-verified per the honesty floor (implements only with test proof; ADR-0279). Same recipe extends to NIS2/DORA/FedRAMP/HITRUST later; FedRAMP additionally inherits the OSCAL baseline/profile artifacts nearly free.
5. **Licensing guardrails (binding):** ADR-0057's ND ban stays absolute (SCF never ingested); ISO/AICPA/PCI TEXT never ships — ids + own paraphrase only; every vendored external catalog must be public-domain/CC0 and hash-pinned; mapping rows carry provenance (`source: nist-sp800-53r5-iso-mapping` vs `own-authored`) and the rollup only _restates_ claims (locked Fork E).

**Migration under the full-retrofit lock:** (a) add the 800-53 axis rows to the 53 existing controls (pointer data, seeded from the public-domain mapping docs, hand-verified); (b) generate the caisson OSCAL catalog from existing `defineFramework` data; (c) re-bless goldens same-change; (d) supersede ADR-0057 with the dual-catalog clarification (own-authored canonical unchanged; CC0 reference catalogs loadable as mapping targets). Zod delta ≈ one optional provenance field on `CrosswalkReference`. No buyer-visible break — packs keep their ids; the spine adds axes.
