# Glossary

Caisson's domain vocabulary in one place: the terms that recur across `specs/`,
`knowledge/decisions/`, and the package READMEs. Each entry is a short synthesized
definition plus a pointer to the canonical owner.

**This file owns the catalog, not the facts.** The canonical source of every term stays
`specs/` + `knowledge/decisions/`. On any conflict, the owning ADR/spec wins. ASCII
punctuation throughout; concatenation shown as `a + b` and the envelope as `[a, b, ...]` to
stay table-safe (the real notation uses bar separators).

Caisson is free and open source (Apache-2.0, ADR-0428) — nothing described below is sold.
One entry (Edition) is kept only because older ADRs still use that vocabulary; where a
term names a package-level building block (credits, manifest attestation, registry
schema), the definition describes what the package does today, not a Caisson-run
commercial flow.

## Terms

| Term                                    | Definition                                                                                                                                                                                                                                                                                                                                                         | Owner                                                                                                                                                                                                                                                     |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AAD** (additional authenticated data) | Context bound into every `field-crypto` AES-256-GCM seal so a ciphertext cannot be moved between tenants, columns, or rows. Base binding is `tenant_id + key_version + column`; the SOC2/HIPAA path adds the row id via `encryptField(..., rowId)`.                                                                                                                | [ADR-0045](../knowledge/decisions/ADR-0045-field-crypto-aead-cipher.md), [ADR-0055](../knowledge/decisions/ADR-0055-field-crypto-cryptoshred-and-row-aad.md), `packages/field-crypto/`                                                                    |
| **AeadCipher seam**                     | The pluggable authenticated-cipher interface `field-crypto` encrypts through. Default is zero-dependency AES-256-GCM via `node:crypto` (FIPS-approved); an alternate cipher is a drop-in without touching callers.                                                                                                                                                 | [ADR-0045](../knowledge/decisions/ADR-0045-field-crypto-aead-cipher.md), `packages/field-crypto/`                                                                                                                                                         |
| **Audit chain**                         | Per-tenant append-only SHA-256 hash chain of evidence entries. Every append mints a fresh length-keyed write-once WORM anchor, so tamper, tail-truncation, and wholesale rewrite are all detectable via `verifyChain(entries, anchor)`.                                                                                                                            | [ADR-0006](../knowledge/decisions/ADR-0006-worm-audit-chain-field-crypto.md), [ADR-0052](../knowledge/decisions/ADR-0052-audit-chain-anchor-persistence.md), `packages/audit-worm/`                                                                       |
| **Base substrate**                      | The base-tier packages every bundle composes over: `kernel`, `tenancy-rls`, `field-crypto`, `auth`, `billing`, `credits` (plus `ai-config`, `mcp-server`, `ui`, `jobs`, `email`).                                                                                                                                                                                  | [specs/01-architecture.md](../specs/01-architecture.md), [ADR-0003](../knowledge/decisions/ADR-0003-composable-package-base-split.md)                                                                                                                     |
| **Bundle**                              | The docs site's module-family grouping for browsing the catalog: Compliance, AI-Production, Local-first, Agentic-Dev, Provenance, and the whole-catalog Everything. Display-only — no price, no purchase id; every member module installs individually from npm. Supersedes the pre-pivot sellable **Edition** below.                                              | [ADR-0257](../knowledge/decisions/ADR-0257-catalog-rework-spec-locks.md), `apps/site/lib/catalog.ts`                                                                                                                                                      |
| **Ciphertext envelope**                 | The self-describing binary layout `field-crypto` stores per encrypted value: `[ver, alg, key_version, nonce, ciphertext, tag]`, base64 into a `text` column. Decrypt reads ver/alg/key-version from the value itself, so rotation and cipher migration need no out-of-band metadata.                                                                               | [ADR-0046](../knowledge/decisions/ADR-0046-ciphertext-envelope-format.md), `packages/field-crypto/`                                                                                                                                                       |
| **Composable composition**              | The architecture law (Option C): a bundle is a composition of base packages plus vertical logic, never a fork, and a package never depends "up" on a bundle (strictly down-only).                                                                                                                                                                                  | [ADR-0003](../knowledge/decisions/ADR-0003-composable-package-base-split.md), [specs/01-architecture.md](../specs/01-architecture.md)                                                                                                                     |
| **Credit / wallet / ledger**            | The `@caisson-sh/credits` package's model: usage as **integer** credits (never floats). A `credit_wallet` holds an integer balance derived from an append-only `credit_event` ledger of grants and debits; idempotency is DB-anchored. A general-purpose metering primitive available to anyone building on Caisson — Caisson's own generator no longer debits it. | [ADR-0007](../knowledge/decisions/ADR-0007-credit-metering-model.md), [ADR-0024](../knowledge/decisions/ADR-0024-credit-idempotency-index.md), `packages/credits/`                                                                                        |
| **Debit-before-spend**                  | The `credits` package invariant: debit the wallet before performing the metered work; insufficient balance returns HTTP **402** and the work never runs.                                                                                                                                                                                                           | [ADR-0007](../knowledge/decisions/ADR-0007-credit-metering-model.md), [ADR-0019](../knowledge/decisions/ADR-0019-error-model.md), `packages/credits/`                                                                                                     |
| **Edition** (historical)                | The pre-2026-07-06 product-unit vocabulary: **Base**, **Compliance** (hero), **AI Production Kit**, **Local-first AI**, **Agentic-Dev**. Dissolved into **Bundle** (above) by the catalog rework (`ADR-0257`/`ADR-0258`, 2026-07-06). Kept here only because older ADRs still say "edition".                                                                       | [ADR-0257](../knowledge/decisions/ADR-0257-catalog-rework-spec-locks.md), [ADR-0258](../knowledge/decisions/ADR-0258-catalog-pricing-consequence-locks.md), [specs/00-product-spec.md](../specs/00-product-spec.md)                                       |
| **Evidence pack**                       | The Compliance bundle's deliverable: a deterministic, golden-fixturable SOC2/HIPAA evidence bundle (RLS / WORM / chain collectors), Ed25519-signed over a canonical manifest plus chain anchor, with a "flag, never guess" rule on missing evidence.                                                                                                               | [ADR-0056](../knowledge/decisions/ADR-0056-evidence-pack-signing.md), [ADR-0058](../knowledge/decisions/ADR-0058-evidence-pack-format-determinism.md), `packages/compliance-core/src/evidence/`                                                           |
| **Fail-closed RLS**                     | Multi-tenant isolation where a missing tenant filter denies rather than leaks: Postgres FORCE row-level security keyed by `SET LOCAL` underneath the app filter, with a schema test. Tenancy denial returns 404 (no existence leak).                                                                                                                               | [ADR-0005](../knowledge/decisions/ADR-0005-fail-closed-rls-tenancy.md), [ADR-0019](../knowledge/decisions/ADR-0019-error-model.md), `packages/tenancy-rls/`                                                                                               |
| **field-crypto**                        | The base package giving per-tenant authenticated field encryption: HKDF-derived keys for dev/self-hosting or request-scoped KMS envelope encryption for a hosted deployment, AES-256-GCM behind `AeadCipher`, a versioned envelope, rotation, and a pluggable `FieldKeyProvider`. The encryption boundary equals the RLS tenant boundary.                          | [ADR-0043](../knowledge/decisions/ADR-0043-field-crypto-per-tenant-keys.md), [ADR-0045](../knowledge/decisions/ADR-0045-field-crypto-aead-cipher.md), [ADR-0046](../knowledge/decisions/ADR-0046-ciphertext-envelope-format.md), `packages/field-crypto/` |
| **FieldKeyProvider (KMS port)**         | The `field-crypto` seam that yields a tenant key: `DerivedKeyProvider` is the zero-infrastructure dev/self-hosted path; `KmsKeyProvider` drives the shipped AWS, GCP, or Azure clients. A hosted deployment can bind Azure-backed historical keys per request and zeroize them at exit.                                                                            | [ADR-0043](../knowledge/decisions/ADR-0043-field-crypto-per-tenant-keys.md), [ADR-0389](../knowledge/decisions/ADR-0389-request-scoped-prefetch-all-kms-context.md), `packages/field-crypto/src/kms.ts`                                                   |
| **Generator / create-caisson**          | The `cli` that composes a tailored repo from the public module catalog (Option C): Zod-`.strict()` selection, catalog validation **before** any path or subprocess, deterministic in-repo template copy + token/JSON-merge (no network beyond installing the chosen packages from npm). Free — no credit metering on Caisson's own path.                           | [ADR-0004](../knowledge/decisions/ADR-0004-generator-registry-codegen-credits.md), [ADR-0048](../knowledge/decisions/ADR-0048-generator-engine.md), `packages/cli/`                                                                                       |
| **Golden-file harness**                 | The regression gate: canonical fixtures (the audit anchor, the generated file set, the evidence pack) checked into `__golden__/` and asserted by `bun test`. Re-bless intentionally with `BLESS=1`. Required before any compliance logic.                                                                                                                          | [ADR-0013](../knowledge/decisions/ADR-0013-testing-golden-file-harness.md), `tooling/testing/`, e.g. `packages/audit-worm/src/__golden__/`                                                                                                                |
| **Manifest attestation**                | The optional `gateAttestation` field a module manifest can carry — a proof marker (e.g. a CI run id) that the standards gate passed for that version. Provenance, not an access-control gate.                                                                                                                                                                      | [ADR-0021](../knowledge/decisions/ADR-0021-registry-publish-pipeline.md), `packages/registry-schema/src/registry-index.ts`                                                                                                                                |
| **MCP server**                          | The `mcp-server` package: a Bearer-authenticated MCP server over a module catalog — `list_modules`/`describe_module` reads, and a `generate` tool that validates every requested `{id, version}` against the catalog index before handing the selection to the host's `onGenerate` hook.                                                                           | [ADR-0008](../knowledge/decisions/ADR-0008-buyer-mcp-server-auth.md), [ADR-0076](../knowledge/decisions/ADR-0076-buyer-mcp-extensibility.md), `packages/mcp-server/`                                                                                      |
| **Module / package**                    | An independently versioned `@caisson-sh/*` package built to the one `tooling/` standard, published to the public npm registry.                                                                                                                                                                                                                                     | [ADR-0001](../knowledge/decisions/ADR-0001-monorepo-tooling.md), [ADR-0003](../knowledge/decisions/ADR-0003-composable-package-base-split.md), `packages/`                                                                                                |
| **Module manifest**                     | The typed (canonical Zod, strict) declaration every module ships: id, version, license, dependencies, description, stability. An unknown field — including a former sellable field like tier or price — is rejected.                                                                                                                                               | [ADR-0020](../knowledge/decisions/ADR-0020-module-manifest-authoring.md), `packages/registry-schema/src/module-manifest.ts`                                                                                                                               |
| **Pro-private firewall**                | The binding build rule: nothing from the pro-private `media-pipeline` repo may seed any package, patterns and ideas only, never implementation. The harvestable license kit is taken from the PUBLIC `tessera` instead.                                                                                                                                            | [CLAUDE.md](../CLAUDE.md), [specs/00-product-spec.md](../specs/00-product-spec.md)                                                                                                                                                                        |
| **Registry**                            | The module catalog contract: `@caisson-sh/registry-schema` defines the manifest and index shapes plus pure helpers (`assertKnownModule`, `assertKnownVersion`) for checking a module id/version against a built index. It is a schema/validation library, not a Caisson-run commerce ledger — packages publish and install through the public npm registry.        | [ADR-0004](../knowledge/decisions/ADR-0004-generator-registry-codegen-credits.md), [ADR-0021](../knowledge/decisions/ADR-0021-registry-publish-pipeline.md), `packages/registry-schema/`                                                                  |
| **Standards gate**                      | The single lint-policy/tsconfig/test + lint-gate source (`tooling/`) every package ships through. In CI it is a required check every package must pass before it publishes.                                                                                                                                                                                        | [ADR-0016](../knowledge/decisions/ADR-0016-ci-cd-standards-gate.md), [ADR-0022](../knowledge/decisions/ADR-0022-import-boundary-lint-gates.md), `tooling/standards-gate/`                                                                                 |
| **WORM**                                | Write-once-read-many evidentiary storage via the `ArtifactStore` port (S3 Object-Lock in prod, local/test doubles in CI). GOVERNANCE retention default with a guarded irreversible opt-in to COMPLIANCE, per-tenant key-prefix isolation, and a 6-7yr retention floor. Anchors the audit chain.                                                                    | [ADR-0051](../knowledge/decisions/ADR-0051-worm-objectlock-retention-mode.md), [ADR-0054](../knowledge/decisions/ADR-0054-worm-artifactstore-port.md), `packages/audit-worm/`                                                                             |
| **withTenant**                          | The sole entry point that opens a tenant-scoped RLS transaction (sets `SET LOCAL` for the tenant, runs the callback inside it). All tenant-bound work, including credit debits and generation, runs inside it.                                                                                                                                                     | [ADR-0015](../knowledge/decisions/ADR-0015-auth-session-rls-seam.md), [ADR-0005](../knowledge/decisions/ADR-0005-fail-closed-rls-tenancy.md), `packages/tenancy-rls/src/rls.ts`                                                                           |
