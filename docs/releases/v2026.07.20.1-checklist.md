recorded by the release-branch refresh under an environment the squashed tag tree does not
reproduce (the known lock-sensitive kernel-pack class). Repaired per the gate's own
prescription: stale row deleted and re-recorded from a pristine frozen-lockfile worktree at the
tag — the re-recorded shasum equals the byte gate's own computation at the tag exactly. This
tag targets the repair commit stacked directly on the v2026.07.20 attestation commit (the
pre-wave tree), NOT current main head, so no post-tag source change at an unchanged version can
trip the gate. The dud v2026.07.20 tag + release await operator deletion (tag mutation stays
operator-only).
