**Context for this ride:** the entire wave shipped during a GitHub Actions **major outage**
(githubstatus.com `Actions: major_outage` from ~16:40Z). Under the operator's same-day lock
("merge on local green"), all five required checks (check · standards-gate · registry-index ·
oscal-conformance · deterministic) were run **locally per PR** with the exact commands the
workflow files define — including a from-Maven oscal-cli 3.2.0 install matching CI's pin — and
every merge below happened only on a fully green local run.

commit `aa6f4f17` before the R4 audit ran. The audit + the byte gate then found **six stale
tarball sidecar rows** — the version branch was cut from `04cf1ff4` before Wave B (#402) merged,
so the consume packed pre-Wave-B bytes for five packages, and the cli template-pin ride-along
(`09ec8e13`) staled a sixth. The rows were re-recorded from the true tree and re-proven
(51/51 catalog packages re-pack byte-identical) in the repair PR this checklist rides in; the
full story is `outputs/audit/release-audit-v2026.08.06.1.md` §3. `v2026.08.06` is a dud tag —
never ridden, no Release published on it, left in place (tag mutation is operator-only).
The sequencing rule this re-teaches: **checklist + audit + byte-gate proof land first, then the
tag** — cut on the attestation commit, from the final post-all-merges main tip.

   the code already shipped. The pre-flight "drained (30 changesets)" box above is true of what
   the cut could see; this deviation is the part it couldn't.
