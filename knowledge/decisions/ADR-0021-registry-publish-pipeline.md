# ADR-0021 — Registry publish pipeline (the one ingress) + versioning

Status: **locked** · 2026-06-27 (D9 module-standards session; locked after 2 adversarial passes)

ADR-0004 fixed the invariant ("a module enters the registry only through the `tooling/` standards
gate; generation meters a credit debit") and deferred the pipeline to D9. This ADR makes that
ingress executable: how a module is versioned, validated, published, and how the registry is the
generator's allowlist. **Host: GitHub Packages** (operator-locked).

## Registry shape: index ≠ source

`registry/` is the **catalog**, not a source mirror. It holds the **registry index**
(`registry/index.json`: each module → its published versions → that version's manifest + publish
metadata) that the CLI, the buyer's agent, AND the docs all read (ADR-0004 one-source for
_metadata_). Module **source** ships as **independently published, versioned packages** to GitHub
Packages (changesets-driven, ADR-0001). `create-caisson` composes a repo by pulling **published
versions named in the index** — it never reads working-tree source. Schema:
`registry/schema/registry-index.ts`.

> Supersedes the "versioned module **sources** live in `registry/`" phrasing of ADR-0004 +
> spec/01-architecture §1's `registry/` comment: sources are published packages; `registry/` is the
> catalog/index. (Still one source for metadata — no contradiction with ADR-0004's intent.)

## Trust model — the index is BUILT, never hand-appended

The earlier draft trusted a `gateAttestation` string ("corresponds to a green run"). That is
forgeable + replayable. Replaced:

- `registry/index.json` is **regenerated by a single CI-only job from the published registry** — it
  is not hand-edited. Branch protection + CODEOWNERS make that job the **sole writer**; a PR that
  hand-edits the file is rejected.
- **Publishing is CI-only** (OIDC / short-lived token); no local publish credential exists, so a
  maintainer cannot `changesets publish` past the gate from a laptop.
- `gateAttestation` (`"<ci-run-id>@<commit-sha>"`) now **records provenance**, it is not the access
  control. Access control is "only CI writes the file + only CI publishes."
- **Rebuild source of truth + bootstrap:** the index is regenerated from a **git-tracked per-module
  version ledger** — each gated publish appends `{id, version, manifest, attestation}` to the ledger
  in the same CI job, and the rebuild reads the ledger (a live GitHub-Packages enumeration can't
  deterministically recover each version's historical manifest). **Bootstrap:** the index starts
  empty; the first gated publish writes the first entry — there is no prior index to validate
  against on a module's first publish (the allowlist is simply empty until then).

## The publish flow — the ONLY registry ingress

```
changeset → version bump → STANDARDS GATE → publish (CI-only) → index rebuilt from registry (CI-only)
                              ├ boundary lint (ADR-0022: AGPL ext+ws · provider-SDK static+graph · down-only · manifest agreement)
                              └ golden-file regression (harness = ADR-0013)
```

The **publish step itself** runs only after a green gate (CI `needs:`), so nothing reaches GitHub
Packages ungated. A buyer entitled to a module may then install that published version directly
(à-la-carte commerce, by design) — but everything in the registry was CI-published through the gate;
there is no ungated path in.

## Versioning (changesets policy)

- **Per-module semver, independent** (à-la-carte commerce, ADR-0003): a module source change
  requires a changeset (CI `changeset status --since` blocks a PR with none).
- **Cascade policy (avoid republish storms):** editions depend on base packages by **range
  (`^`)**, and `updateInternalDependencies: false` — a base **patch** does NOT force every edition
  to republish; editions bump intentionally when they adopt a breaking base change. (The earlier
  `updateInternalDependencies: patch` would cascade a kernel patch through every edition — review MED.)

## Golden-file at publish

The module's **golden fixture** (ADR-0020 `golden`) runs inside the gate via the ADR-0013 harness —
this track does not redefine the runner. A _module's_ fixture = the serialized, deterministic output
for a fixed input (a generated file set, an evidence-pack manifest, a composed config), committed
under the module's `golden` dir. A golden diff **blocks publish** until re-blessed (ADR-0013).

## Generator input-validation (ADR-0004/0008 enforcement)

The **registry index IS the allowlist**. `create-caisson` + the buyer MCP server load it via
`loadRegistryIndex()` (parse-or-throw — never a cast) and validate **both** the module id
(`assertKnownModule`) **and the version** (`assertKnownVersion`) against the index **before any path
construction or subprocess**. Version matters: a raw version string (`"0.1.0/../.."`) reaching a path
is a traversal surface (review HIGH). The slug regex is re-asserted inside the check as
defense-in-depth. The MCP write path is also credit-gated + per-account rate-limited (ADR-0008).

## Backfill (topological)

P2–P4 packages become the initial registry module set through this exact flow — but **in dependency
order**: `kernel → base packages → compliance primitives → editions → app-templates`. An edition
can't first-publish before its base deps exist in the registry. (The earlier "no special path / each
module's first publish" ignored ordering — review MED.)

## Rejected

- **Trusting an attestation string** — forgeable + replayable; build-from-registry + CI-only writer instead.
- **Source blobs in `registry/`** — duplicates packages, breaks reproducible install + per-module changelogs.
- **Local publish credentials** — a laptop publish bypasses the gate; CI-only.

## Binding

**Target state (full enforcement lands with the publish/generator code at P5):** nothing enters the
registry except via a CI-only gated publish; `registry/index.json` is rebuilt by CI only (sole
writer); every generation validates module **id + version** against the index allowlist before any
path/subprocess; each module is independently versioned with `^` internal ranges.

**Enforced now (this track):** the standards-gate runs in the CI `standards-gate` job (pre- and
post-install, ADR-0022); `.github/CODEOWNERS` gates hand-edits to `registry/index.json` + the ADRs +
the board (requires branch protection + a real owner handle to bite); the allowlist helpers
(`loadRegistryIndex` / `assertKnownModule` / `assertKnownVersion`) exist for the generator to call.
The publish step, the CI index-writer job, and the generator itself are P5 — until then the
target-state bullets are design, not running code.
