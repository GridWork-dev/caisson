# ADR-0242 — Visual-audit remediation picker: eyebrow voice, real media, mobile buy rail

**Status:** accepted · 2026-07-04 (site-design session, operator picker). Resolves the three
genuine judgment-call forks surfaced by the 221-finding visual audit (`tooling/design-critic/findings.toml`,
workflow `visual-audit`, all 48 public routes at mobile+desktop × light+dark). Everything else in
that ledger has an unambiguous correct fix and needs no lock — it routes straight to the
remediation specs. Append-only; supersede with a later ADR, never edit. **Tags:** `ui`, `frontend`.

## Decision

| Fork                                                                                                                                                                                                                                                                                                       | Lock                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Eyebrow-on-every-section voice** (~20 findings across nearly every route — the `.cs-eyebrow` accent kicker repeats on almost every section, which the impeccable skill's Absolute Bans names as AI-scaffolding, even though DESIGN.md/ADR-0078 locks the eyebrow in as one of 5 sanctioned accent slots) | **Vary treatment per section** — keep the eyebrow as a system primitive, but differentiate wording/weight per section so the repetition reads as deliberate voice rather than reflexive scaffolding. The tokenized `.cs-eyebrow` component and its accent budget stay; the remediation is copy/usage-pattern work across every marketing/docs/glossary/legal page template, not a component removal. |
| **Empty illustration placeholders** (13 findings — module depth pages and a few others ship a live but content-free blueprint/dot-grid box where real media belongs)                                                                                                                                       | **Reaffirm deferred.** This is the pre-existing, operator-locked ADR-0237 F2 gap ("media slot ships with placeholder brand art — real media is a later phase, TBD"), not a new discovery. These 13 findings are marked `accepted` in the ledger rather than queued for a fix; revisit when there's real design bandwidth for 11+ bespoke diagrams/screenshots.                                       |
| **Mobile buy-rail position** (9 findings — every module depth page's price/Add-to-cart card sinks to the very bottom of the page on mobile, after the full FAQ, because the responsive grid collapses to one column with no reorder)                                                                       | **Sticky bottom bar** — a persistent price + Add-to-cart bar pinned to the mobile viewport bottom on module depth pages, the standard e-commerce mobile pattern. This is a bigger lift than a simple DOM reorder (new sticky-positioned component, safe-area/notch handling, z-index above the existing scale, dismiss/scroll behavior) and touches all 11 module depth pages' shared layout.        |

## Consequences

- The eyebrow-voice fork becomes a copy workstream in the remediation spec (`outputs/specs/visual-audit-remediation/`), not a design-system change — no token/component removal, no re-approval of the ADR-0078 accent budget.
- The real-media dismissal closes 13 ledger entries as `accepted` with no code change; `docs/state/opportunity-backlog.md`'s existing F2 line is the tracking record, this ADR just confirms the audit didn't surface new information forcing a re-open.
- The sticky mobile buy-rail is scoped as its own remediation workstream (new shared component in `packages/ui` or `apps/site/components`, wired into the module depth-page template) rather than folded into the smaller systemic-CSS fixes.
- Every other finding in the ledger (mobile code-block scroll affordance, footer placeholder contrast, nav-tab overflow, related-terms link affordance, restated headings, the broken Agent-runner icon, the garbled alerting-module copy, the mobile price-truncation bug, the em-dash/aphoristic-cadence copy sweep) has an unambiguous fix and is scoped directly in the remediation spec with no operator pick needed.
