# ADR-0014 — Database, ORM, and migration strategy

Status: proposed · 2026-06-27 (foundations track; resolves the open DB/ORM fork)

The ORM is **Drizzle** (already implied across the spec set — made explicit here): typed
schema-in-TS, SQL-first, first-class RLS-policy authoring, and one schema that drives prod,
local, and test drivers. The reference/seller-platform Postgres host is **Neon** (operator
lock): serverless Postgres with **database branching** → a per-PR ephemeral DB for the
fail-closed-RLS CI job, a generous free tier for a solo operator, Drizzle-first DX. The host
is swappable by connection string (a buyer's shipped app points `DATABASE_URL` anywhere) —
Neon is the _default_, not a hardcode.

**Driver matrix (one Drizzle schema, three drivers):** Neon serverless
(`drizzle-orm/neon-http` / `neon-serverless`) in prod · node-postgres (`drizzle-orm/node-postgres`)
for a local Postgres · **PGlite** (`drizzle-orm/pglite`) for tests (ADR-0013). RLS, `SET LOCAL`,
and `SET ROLE` behave identically across all three.

**Migration strategy (← health-service / Wardfile pattern).** Migrations are **numbered,
forward-only SQL** generated by `drizzle-kit` into `migrations/NNNN_*.sql`, applied in order
and **idempotently** (each guarded / safe to re-run). Drizzle's own `__drizzle_migrations`
ledger records what ran; on top of it a **`schema_version` table** records every applied
migration's number + a content **checksum** + `applied_at` — so a drifted/edited migration is
detected, not silently re-applied. **RLS policies live inside migration files** (drizzle-kit
does not emit RLS): every tenant-owned table's `ENABLE ROW LEVEL SECURITY` + `FORCE` + policy
ships in the same migration as the table (ADR-0005), so a table can never land without its
policy.

Rejected: Prisma (heavier, weaker raw-SQL/RLS-policy story, extra engine). Schema-per-tenant
(no clean Drizzle multi-schema migration story — ADR-0005). An ORM-managed auto-diff with no
numbered files (non-reproducible generation; per-module changelogs need stable migration ids).
Hardcoding Neon (kills the buyer's host choice — it is a connection-string default only).

Binding: one Drizzle schema, three drivers; migrations numbered + idempotent + checksum-ledgered;
every tenant table ships its RLS policy in the same migration; `DATABASE_URL` is never hardcoded.
