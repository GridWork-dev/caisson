# Method

## Run order

1. Define run id, scope, mode (`quick`, `standard`, or `exhaustive`), rings, viewports, and themes.
2. Generate and inspect the manifest. Remove a surface only with a stated reason.
3. Complete current Exa research. Record dated sources and claims; do not reuse an old lock silently.
4. Search Refero styles, screens, and flows in that order. Lock a small coherent set; do not blend unrelated references.
5. Load Caisson product/design context and the relevant Impeccable register.
6. Run credential/profile/cleanup preflight.
7. Execute journeys goal-first. Record unreachable states honestly.
8. Replay P0/P1 behavior findings from a clean profile.
9. Revert and verify every mutation before the next mutation.
10. Validate evidence, reconcile findings, write report and picker, then stop. Never commit automatically.

## Modes

- Quick: Ring 1, desktop and mobile, light/dark on high-risk routes.
- Standard: all selected rings, primary/negative/recovery paths, one clean replay for P0/P1.
- Exhaustive: all rings and boundaries, three independent P0/P1 replays, degraded dependencies where safe.

## Reference lock

For each locked reference record source, exact screen/style/flow id or URL, observed principle, Caisson adaptation, and rejection boundary. A reference is evidence, not a mandate to copy visual identity.
