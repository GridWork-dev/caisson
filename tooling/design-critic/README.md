# @caisson/design-critic

The **advisory** layer of the three-layer design-quality model (ADR-0101 Layer 3). It is the
counterpart to the **deterministic, blocking** gates (#1–#6) — and unlike them it **never gates a
merge**. A `gw-frontend-designer`-style pass scores a surface on the Nielsen heuristics and emits
findings; this package gives those findings durable identity and reconciles them run-to-run.

## Why a ledger (not a fresh dump each run)

A rubric score swings ±6 between runs (ADR-0101 Rejected: "Block on the critic's rubric score"), so
the score must never block. But the _findings_ are worth tracking — if a finding keeps reappearing, or
an operator has triaged one as `accepted`, that state must survive a reword. Hence:

- **Stable id** = `sha256(workflow ∷ surface ∷ normalized-title)[:16]` — the normalized title drops
  case/punctuation/whitespace, so rewording a finding never forks it into a new row.
- **reconcile()** classifies every id each run: `new` / `unchanged` / `regressed` / `closed`. A
  `fixed` finding that reappears flips to **regressed**; an `accepted` finding keeps that status while
  it persists; a finding that disappears flips to **fixed** (class `closed`).

## Use

```bash
# pipe a fresh critic run (JSON array of {workflow, surface, title, severity, status?})
bun run tooling/design-critic/src/cli.ts run.json
# → rewrites findings.toml, prints: "design-critic: N in ledger · … (advisory — never blocks)"
```

`findings.toml` is the persisted ledger; the operator hand-edits only the `status` field
(`open`→`accepted` to triage). Everything else is regenerated by `reconcile()`. The CLI **always exits
0** — this layer informs, it does not gate.
